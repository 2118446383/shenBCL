# shenBCL 0.3.6 安全检查与验收记录

日期：2026-11-20。范围为当前桌面启动器的账号授权、凭据处理、日志读取、IPC、下载／ZIP 路径边界及依赖公告。本文记录本轮能复现和验证的结果，不代表已证明不存在其他漏洞，也不是 Mojang／Microsoft 的审核结论。

## 本轮修复

| 问题 | 修复与验证 |
|---|---|
| Xbox 授权头、identityToken、RpsTicket 等在部分日志格式下未完整脱敏 | 覆盖完整 XBL3.0 凭据及 OAuth／常见敏感字段；增加回归检查，普通日志仍可阅读 |
| logs／crash-reports 目录联接可使日志查看器读取实例外文件 | 拒绝链接目录及链接文件，打开后校验文件身份；回归覆盖普通日志和两种目录联接 |
| 设备代码过期后可能继续发起轮询；取消的旧响应可能干扰新流程 | 按授权截止时间限制等待和请求，响应前后检查取消状态；过期及取消／重启场景通过 |
| 授权响应读取无明确体积边界，Xbox／令牌字段检查不足 | 响应体限 1 MiB，读取过程受超时／取消约束；校验令牌、用户哈希与有效期 |
| Minecraft 服务拒绝可能误报成用户取消微软授权 | 按服务来源区分 OAuth 错误；Minecraft 403 提示检查应用审批和账号权限，不声称一定由审批导致 |
| 损坏的本机账号偏好 JSON 可能阻止启动 | 严格规范化结构及字段，忽略损坏 ID／皮肤；本机偏好与加密记录分别有读取大小限制 |
| 本地能力的调用边界进一步收紧 | IPC 限可信主框架；其他窗口／导航受限；仅可信界面可请求写入剪贴板，不开放读取、相机或麦克风权限 |

## 账号流程现状

已配置项目所有者自己的公开应用 Client ID，未采用其他启动器的应用身份。设备代码端点已返回 HTTP 200、有效用户代码及官方验证网址；此次检查未输入玩家凭据、未持久化账号授权。

账号主进程具备 Microsoft → Xbox Live → XSTS → Minecraft 的交换路径，验证 Java 版资格和角色资料，并同步皮肤／披风。访问及刷新令牌不返回渲染器，保存时使用 Windows 支持的 Electron safeStorage；加密不可用时阻止建立需要保存的登录。

界面支持显示、复制设备代码、打开固定官方网址、倒计时及取消。主按钮复制代码后打开网页，剪贴板不可用时提示手动输入。缓存角色与已在线验证的身份分开显示；失效或无法刷新时不静默改成离线身份。

Minecraft API 申请／审批和真实账号完整验收仍待完成。现有独立离线模式有明确标记，不能在申请材料中声称整个程序的所有启动都强制正版认证。

## 仍需人工／外部验收

1. 确认 Minecraft Services 应用接入获准，然后由账号所有者在微软网页完成真实授权。
2. 检查正版身份、皮肤／披风、重启恢复、撤销授权后的重新登录及完整游戏启动。
3. 不同机器的系统代理、Windows 凭据加密与图形驱动仍需实机覆盖。
4. Java、模组、加载器处理器等会在用户明确操作时执行本机代码；本应用未承诺隔离这些代码的沙盒。
